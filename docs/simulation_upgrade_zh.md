# 相机抓取与路径避障改造

## 实现

1. `scene_camera.py` 发布同时间戳的 RGB、32FC1 米制深度、CameraInfo 和相机光学坐标系在 base_link 中的位姿。场景相机改为斜俯视，以减少手腕遮挡目标。保留原有 overhead_rgb 话题名以兼容接口。
2. 抓取入口默认由 `yolo_detection.py` 使用 YOLO 类别、D435 深度和 TF 获取物体位置；`rgbd_detection.py` 的 OpenCV HSV 颜色分割保留为备用。共享 `rgbd_detector.py` 不订阅 object_states，不按颜色查表取得物体坐标。无图像、无效深度或过期帧输出空检测。
3. 抓取根据可见顶面换算当前模型 TCP 抓取高度；不采用明显被遮挡而缩小的轮廓来重新对准。接近方形的物体使用稳定抓取方向。抬升结果仍来自相机深度，不以动作完成代替成功。
4. `rebotarm_planning/collision_planner.py` 使用私有 MuJoCo 模型检查关节路径；直线路径受阻时进行有预算限制的 RRT 搜索和路径简化。默认每段最大关节采样间隔 0.025 rad，接触间隙 2 mm。执行中重新检查反馈至下一指令的路径；无路径或碰撞则失败并保持测量姿态。
5. 只允许选定目标与两个夹指接触。检测到双指接触后，以抓取物体相对手腕的变换预测载荷外形，检查其与场景的穿透。这是保守的刚性抓持近似，实际滑移仍由物理引擎决定。
6. 轨迹动作等待实际反馈在 0.025 rad 内持续 0.2 秒；反馈超时、跟踪误差超过 0.35 rad 或到位超时返回失败。不再将目标位置覆盖到测量状态。速度时长计算考虑三次平滑插值的 1.5 倍峰值速度。
7. 同时只能运行一个路径执行；取消动作保持测量位置。修复 hardware.launch.py 缺少导入的问题。

## 范围

- 检测对象为本场景红、蓝、黄规则物体，采用 RGB-D，不是通用物体识别模型；真实硬件需要 RGB-D/双目或其他深度来源及外参标定。
- 碰撞地图来自已知 MuJoCo 场景及其动态物体状态；抓取定位和成功判定来自相机。尚未实现 RGB-D 点云→任意未知障碍物地图。
- 路径检测是离散采样，不是连续碰撞证明；几何的接触屏蔽沿用现有模型配置。非凸网格、极薄障碍物、快速动态障碍物仍需要更严格检查与速度约束。
- 绕障会改变原轨迹时间，不保留原轨迹速度/加速度字段；适用于当前低速抓取，不适用于颠球实时轨迹。关节空间插值也不保证 TCP 严格直线下降。
- 夹爪开合服务当前仍是目标接受语义；抓取流程保留闭合等待，并用图像确认物体抬升。
- 相机默认 320×240、8 Hz，只适合低速抓取。遮挡或深度无效会导致失败，不回退到仿真物体真值。
- 包含 UART 七轴主机适配，但不包含 STM32 固件或真机标定。

## 启动

已有 ROS Humble 和现有 install/ 接口构建产物的这台机器可运行：

```bash
cd /home/wq/reBotArmController_ROS2-main
./scripts/start_camera_sim.sh
```

脚本显式使用本项目的源码、场景和仿真 authority_mode，不启动真机 CAN 驱动。默认无窗口，便于 EGL 环境运行；有桌面 OpenGL 时可用 `MUJOCO_GL=glfw REBOTARM_VIEWER=true ./scripts/start_camera_sim.sh`。

另一个终端可执行：

```bash
cd /home/wq/reBotArmController_ROS2-main
source /opt/ros/humble/setup.bash
source install/setup.bash
export PYTHONPATH="$PWD/src/rebotarm_agent:/home/wq/.local/lib/python3.10/site-packages:${PYTHONPATH:-}"
ros2 run rebotarm_tasks pick --color red --action-timeout-padding-sec 40
```

可以将 red 改为 blue 或 yellow，每次独立实验前重置场景。不要同时启动 FakeRsDriver 作为另一套关节状态/运动接口提供方。

单元测试需要可导入 mujoco、OpenCV、NumPy、SciPy、pytest：

```bash
PYTHONPATH="$PWD/src/rebotarm_mujoco_rs:/home/wq/.local/lib/python3.10/site-packages:${PYTHONPATH:-}" \
MUJOCO_GL=egl python3 -m pytest -q tests/test_sim_upgrade.py tests/test_uart_protocol.py
```

`tests/ros_smoke.py` 为无硬件的 ROS 集成实验，会实际运行仿真抓取；应使用独立 ROS_DOMAIN_ID，避免干扰其他 ROS 会话。该实验运行时间取决于 IK、规划和渲染性能。

## 仿真与真机距离

现有模型有重力/接触、PD、力矩限幅、速度限幅及简化电机模型，但未完成实机参数辨识。当前实际电机映射是 J1～J3 DM4340P、J4/J6 DM4310、J5/夹爪 PA43；`rs_*` 是兼容入口名。质量和电机力矩使用当前配置，摩擦、转子惯量和热参数仍需实测。

当前可验证软件接口、低速抓取流程、基本几何和碰撞；不能给出“与真机接近多少百分比”，也不能直接用来预测高速球拍反弹或强化学习迁移成功率。

下一步需用实机数据校准：关节零位/方向与 TCP、质量/质心/惯量、实际电机型号及扭矩常数、摩擦/死区/回差、控制延迟/抖动、相机延迟/标定误差。用相同轨迹比较 q/dq/电流或力矩、末端轨迹、跟踪相位差和抓取成功率。

## 持续向上颠球路线建议

先建立高速视觉→球位置/速度估计→落点和撞击时刻预测→球拍位姿/速度目标→关节控制的基线。球拍姿态决定水平纠偏，撞击前球拍法向速度调节下一次弹起高度。STM32 负责稳定周期的电机命令、插值和本地约束；LLM/MCP 不进入实时控制环。

摄像头先评估 120 fps 量级及曝光/运动模糊，控制更新可从 250 Hz 联调起步，再由总延迟、CAN 负载和电机带宽决定。这是工程起点，不是已经验证的最低配置。现有 8 Hz 相机和 60 Hz Python 路径执行不适合直接承担颠球闭环。

建议先做 PD/预测控制或 MPC；若实际反弹、旋转和气动误差明显，再考虑残差强化学习，对基线控制器的拍面姿态或法向速度作有限修正。训练先在仿真中完成，并随机化质量、反弹系数、摩擦、球旋转、相机误差、控制延迟和电机响应；先验证域随机化范围与实测一致。

目前场景没有球拍、乒乓球的有效反弹标定或相应训练环境。直接端到端 RL 容易学会利用理想仿真误差，应先补物理实验与稳定控制基线。持续单球颠球的任务结构较明确，不需要一开始就用 RL。

## 乒乓球逻辑归档状态

乒乓球与球拍几何体已从抓取场景移除，避免干扰抓取碰撞规划。控制器保留在 `rebotarm_tasks/pingpong_controller.py`，白球检测保留在 `rebotarm_vision/rgbd_detection.py`，当前抓取启动文件不会运行它们。以后恢复颠球时应新建独立 `pingpong_scene.xml`，不要把球和球拍重新加入 `grasp_scene.xml`。

建议按“单次接球 → 连续两次 → 连续颠球”建立独立 Gymnasium/MuJoCo
训练环境。动作优先使用末端期望速度或关节速度残差，底层仍经过现有的关节限位、
速度限位和力矩限位；观测至少包含关节位置/速度、球的位置/速度、球拍位姿和上一
动作。奖励应同时约束球的目标顶点、落点与拍面中心误差、连续触球次数、动作平滑、
力矩利用率和关节限位距离。训练时随机化球质量、恢复系数、摩擦、空气阻力、相机
延迟/噪声和电机响应，再用低速策略上真机。腕部 D435 适合抓取，但高速颠球建议另加
固定高速全局快门相机；快速小球仅靠移动中的 D435 深度图容易受视野、运动模糊和延迟影响。

## 双指物理抓取判定

当前 CAD 夹指 STL 为凹形网格，MuJoCo 会按凸包参与碰撞，凸包会早于可见夹指碰到
物体。模型因此将夹指网格设为仅显示，并用与可见指尖对齐的薄接触面进行物理碰撞。
`/rebotarm/mujoco/object_states` 会为每个物体发布 `finger_contacts`、
`support_contacts` 和 `contact_pairs`。抓取状态机在抬升前必须确认左右两指同时接触，
抬升后还要再次确认双指保持；单侧摩擦带起物体不再算作成功抓取。

## 本次验证结果

- 8 项自动化测试通过：真实场景 RGB-D 定位/位移/抬升、无效深度、实际模型碰撞目标拒绝、绕障搜索、CRC 标准向量、分包/粘包、坏帧重同步及截断帧恢复。
- ROS 物理仿真联调中红、蓝、黄各完成一次全流程抓取；相机测得抬升分别约 38.8、40.3、36.4 mm。每次抓取前还验证小幅关节动作依据测量反馈结束。
- 这是固定场景的功能验证，不是随机场景成功率统计，也不是实机验证。碰撞失败案例：原 TCP 高度 0.14 m 被判断为夹指与桌面碰撞并拒绝执行；修正为基于相机顶面高度后完成抓取。


## 慢速仿真抓取回归修复（2026-09-19）

旧版按墙钟推进轨迹，但物理仿真按固定步长推进。在 GUI 或 CPU 负载使仿真变慢时，命令会超前，触发 `joint tracking error exceeds 0.35 rad`。已经在独立 ROS 进程中用延迟物理回调复现。

修复后每段轨迹依据实测关节位置限制命令超前量到 0.08 rad；仿真慢时相应延长执行时间。0.35 rad 误差保护、碰撞检查、取消和实测终点检查仍保留；连续 4 秒无明显运动进展会报错。viewer 刷新默认 30 Hz，物理步长不变。当前 RS 模型夹爪打开、闭合改为检查实际手指位置稳定，闭合受阻时允许接触判断，最终仍由相机验证物块抬升。

新增 10 项回归测试覆盖慢速反馈、卡住、碰撞、取消、大误差及夹爪反馈。独立 ROS 进程、物理回调每次额外延迟 16 ms 的完整红色物块抓取成功，耗时 53.43 s，相机验证抬升约 39.9 mm。工具环境 GLFW/GLX 无法创建窗口，未完成 GUI 验证。

修改后必须退出旧仿真进程并重新启动。`scripts/start_camera_sim.sh` 会优先导入源代码，无需为这些 Python 修改重新构建。抓取客户端的 2 秒 duration 是轨迹时长请求，不保证慢速仿真中 2 秒墙钟完成；保留 40 秒 action timeout padding。


## 共享任务与规划重构（2026-10-10）

当前入口为 `rebotarm_bringup/grasp.launch.py backend:=mujoco/sdk/uart`，
`start_camera_sim.sh` 也使用这个统一入口。
抓取状态机与夹爪等待迁到 `rebotarm_tasks`；规划迁到 `rebotarm_planning`；
MCP 只注册工具并调用共享任务。旧入口保留转发以兼容已有命令。

### 这次修正的实际问题

- URDF 原 CAD 基座缺少 MuJoCo 已有的固定旋转，导致同一关节姿态的 TCP 坐标
  差约 0.35～0.48 m。新增统一的直立 `base_link` 与固定 CAD 基座变换，未移动
  物理机械臂。TCP、D435 光学坐标和重力方向都经过多姿态回归。
- 仿真第七轴反馈是 N，PA43 是 Nm；以前共用数值容易误解。现在由独立转换器
  输出统一状态，闭合接触候选要求开度稳定、受力且未到机械全闭终点。
- SDK 夹爪限制的是主机计算的总 PD 力矩，再用零 Kp/Kd MIT 输出。只限制
  feed-forward 项不能限制电机内部 PD 总输出。PA43 未配置限矩时拒绝命令。
- 硬件载荷登记改为同步服务确认；登记失败不会继续抬升。硬件碰撞图来自真实
  RGB-D 和标定桌面，不订阅仿真物体真值。
- 扫描器的额外载荷改施加在 TCP，避免把物体质量错误地加到手腕原点。
- 红色物块抬升路径接近 J4 下限，视觉保持高度卡在 35 mm 门槛附近。
  改为先抬升再收回 25 mm，最终高度 0.24 m，成功门槛仍为 35 mm。
- 圆柱轮廓因遮挡略变时，旧方向门槛会触发大幅转腕。近圆形轮廓现在保持方向，
  长条物体按双指夹爪的 180° 对称性减少转腕。

仿真双指碰撞仍是附加证据，所有后端最终都必须用新 RGB-D 帧确认抬升并保持。
规划中的载荷预测不焊接物体、不改变仿真物体位置。

真机默认标定状态为 false，PA43 接触阈值/限矩为零。需要真实手眼、TCP、夹爪
标定和固件联调后才能运行完整抓取。当前 motorbridge 没有 CAN 接收时间戳，
ROS 消息过期检查不能证明缓存电机反馈来自最新 CAN 帧，这项需在驱动联调补齐。
本次没有连接实体电机。
