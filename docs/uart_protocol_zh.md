# UART 固定帧协议（STM32 七轴）

本文按已烧录的 `te (2).zip` 源码核对；早期附件 `motor_fix_complete.md` 只作历史参考。七轴 UART 使用固定长度：

- **主机 → STM32：72 字节**
- **STM32 → 主机：131 字节**
- UART：8N1，当前上位机配置 **3000000 baud**，STM32 必须使用相同波特率
- 主机指令发送 **100 Hz**；`te (3)` 源码的反馈仍为 **50 Hz**，内部控制为 **200 Hz**

## 槽位和实体关节映射

实体电机顺序是：**J1～J3 = DM4340P，J4/J6 = DM4310，J5/J7 = PA43**。
STM32 固件的线槽位仍按电机组排列；上位机在发送和接收时使用
`slot_joint_ids=[4,6,1,2,3,5,7]` 重排，因此不会改变每个逻辑关节对应的实体电机。
`joint1..joint6, gripper` 仍是 ROS 和任务层使用的逻辑顺序。

主机生成绝对位置目标并做上层限速；当前已烧录固件还会在 STM32 内部以 5 ms 周期做位置插值，再转换成 CAN。若要让下位机只执行，需另行修改并重新烧录固件。

## 1. 72 字节指令

帧布局：

```text
AA
轴1 10字节
轴2 10字节
轴3 10字节
轴4 10字节
轴5 10字节
轴6 10字节
轴7 10字节
55
```

总长度为 `1 + 7×10 + 1 = 72` 字节。每个轴块使用小端序：

| 块内偏移 | 类型 | 物理含义 | 换算 |
|---:|---|---|---|
| 0..1 | int16 | 绝对目标位置 | `q_des = value / 1000` rad |
| 2..3 | int16 | 位置轨迹限速，固件取绝对值 | `speed_limit = abs(value) / 1000` rad/s |
| 4..5 | uint16 | Kp | `Kp = value / 1000` |
| 6..7 | uint16 | Kd | `Kd = value / 1000` |
| 8..9 | int16 | 前馈力矩 | `tau_ff = value / 1000` Nm |

轴块按 STM32 线槽位排列；括号内是 CAN 反馈/Master ID：

| 线槽位 | 逻辑关节 | STM32 处理组 | 实体型号 | 本地 Motor ID | 反馈/Master ID |
|---:|---|---|---|---:|---:|
| 1 | joint4 | J4310 | DM4310 | 0x01 | 0x04 |
| 2 | joint6 | J4310 | DM4310 | 0x02 | 0x05 |
| 3 | joint1 | J4340P | DM4340P | 0x08 | 0x11 |
| 4 | joint2 | J4340P | DM4340P | 0x09 | 0x12 |
| 5 | joint3 | J4340P | DM4340P | 0x14 | 0x13 |
| 6 | joint5 | Motorevo | PA43 | 0x01 | 0x06 |
| 7 | gripper/joint7 | Motorevo | PA43 | 0x02 | 0x07 |

指令帧没有轴 ID，STM32 严格按线槽位选择 CAN 电机；上位机负责把逻辑关节目标重排到该顺序。

### 位置语义

当前固件按**相对启动零点的绝对位置**接收目标，再由内部限速轨迹追踪；它不执行位置累加：

```text
current_position += received_position
```

MCU 每次复位都会发送电机设零命令，把当时的位置定义为零点。它不是机械回零；URDF 关节零点、方向及实际限位仍需标定。UART 默认关闭模型重力前馈。

### 量化范围

固定整数限制对应：

- 位置：约 -32.768 .. 32.767 rad
- 速度：约 -32.768 .. 32.767 rad/s
- Kp：0 .. 65.535；Kd 虽用 uint16，但固件只接收 0 .. 5
- 力矩：约 -32.768 .. 32.767 Nm

上述是整数表示范围。固件位置范围为 ±12.5 rad，实际还受机械限位限制；速度和前馈力矩分别按线槽位受 `[0.3,0.3,0.3,0.3,0.3,0.5,0.5]` rad/s、`[10,10,1,1,1,3,3]` Nm 限制。主机先将这些上限映射回逻辑关节，再采用固件、配置和电机峰值中的较小值，拒绝越限指令。

位置按 0.001 rad 编码。CAN 反馈在零点附近可能有约 ±0.000191 rad 的量化差；主机仅在该位置编码后合法时接受边界误差。模型边界若不是整毫弧度，发送刻度向限位内取整，保证编码后仍在原限位内。原始反馈角度保持不变。

## 2. 131 字节反馈

帧布局：

```text
BB
轴1 18字节
轴2 18字节
轴3 18字节
轴4 18字节
轴5 18字节
轴6 18字节
轴7 18字节
flags0 flags1 flags2
44
```

总长度为 `1 + 7×18 + 3 + 1 = 131` 字节。

前五个 STM32 达妙处理组反馈块（不代表实体电机型号）：

| 块内偏移 | 类型 | 含义 |
|---:|---|---|
| 0 | uint8 | 固件本地 Motor ID：`1,2,8,9,0x14,1,2` |
| 1 | uint8 | 状态：0 失能，1 使能，8..E 故障 |
| 2 | uint8 | 反馈新鲜标志 |
| 3 | uint8 | MOS 温度（摄氏度编码） |
| 4 | uint8 | 转子温度 |
| 5 | uint8 | 保留 |
| 6..9 | float32 | 位置 rad |
| 10..13 | float32 | 速度 rad/s |
| 14..17 | float32 | 力矩 Nm |

后两个 Motorevo 反馈块：

| 块内偏移 | 类型 | 含义 |
|---:|---|---|
| 0 | uint8 | 固件本地 Motor ID：`1,2,8,9,0x14,1,2` |
| 1 | uint8 | 使能标志 |
| 2 | uint8 | 反馈新鲜标志 |
| 3 | uint8 | 线圈温度编码，摄氏度为 `value - 40` |
| 4..5 | uint16 | 状态字，小端 |
| 6..9 | float32 | 位置 rad |
| 10..13 | float32 | 速度 rad/s |
| 14..17 | float32 | 力矩 Nm |

反馈块按线槽位返回；块内本地 ID 不是逻辑关节号。上位机用
`feedback_motor_ids` 校验本地 ID，再按 `slot_joint_ids` 映射到逻辑关节。
CAN Master/反馈 ID（4,5,0x11,0x12,0x13,6,7）不在线路中传输。

flags 在整帧偏移 127、128、129，分别属于 STM32 的 J4310、J4340P、Motorevo 处理组；这些组名来自当前固件实现，不是实体关节型号。

- bit0：命令新鲜
- bit1：对应电机组运行
- J4340P/Motorevo 的 bit2..5：停机原因
- J4340P/Motorevo 的 bit7：未初始化

主机使能成功要求三组都运行、命令新鲜且七轴使能。Motorevo 状态字 bit0 是使能位，`status & 0xfffe` 是故障位，与固件解析一致；完整状态字仍保留在诊断中。反馈新鲜标志为 0 时，位置、速度和力矩不作为新测量发布。

## 3. 使能、失能和看门狗

附件固定帧没有独立的 ARM、DISARM、ACK、序号或 CRC 帧。因此当前主机策略是：

1. STM32 上电后保持失能，继续发送 131 字节反馈。
2. ROS 调用 `/rebotarm/enable` 后，主机确认 UART 整包仍在更新、各组已初始化，且没有已知故障、新鲜的轴使能状态或组运行位。首次发送不要求各轴 CAN 新鲜，也不等待位置适配器先生成目标。
3. 主机先周期发送零限速、零 Kp/Kd、零前馈的 72 字节帧，触发 STM32 使能；位置字段为 0，但限速为 0 会暂停固件位置轨迹，零增益不会按该位置产生位置力矩。主机等待本次发包后的七轴新鲜反馈、七轴使能及三组运行/命令新鲜标志。确认超时则停发并报错。
4. ROS 调用 `/rebotarm/disable` 或上游目标超时后，主机停止发送；服务成功表示已停发，实际停机由 STM32 看门狗完成。
5. 收到普通目标不能绕过主机使能门，也不能清除锁存故障。

使能确认时才用新测量检查正常目标的起始偏差（默认 `start_tolerance=0.15 rad`）。若上游还在等待测量，主机会短暂保持新实测位置、零增益和零前馈，给适配器接管；此临时目标同样受 120 ms 上游超时限制。进入正常控制后，任一轴 CAN 反馈过期立即停发；过期缓存不会作为新测量发布。

当前参数：

- 主机指令周期：10 ms（100 Hz）
- UART 反馈周期：`te (3)` 源码为 20 ms（50 Hz），由 STM32 配置
- STM32 看门狗：当前固件为 500 ms；主机目标新鲜度应明显小于该值
- 上位机 MIT 目标新鲜度：300 ms（超时停发；随后由 STM32 看门狗失能）
- 反馈超时：250 ms
- STM32 的 CAN 反馈超时和使能确认超时均为 100 ms

当前源码在命令超时后取消待发目标，再发送 CAN 失能；没有重力负载受控减速或抱闸流程。实际停止延迟还受主循环、CAN 排队及电机响应影响。

看门狗时间和动作在 STM32 固件配置，固定 72 字节没有该字段，主机不能远程修改。

位置不变化时也要持续发送完整 72 字节作为保活。速度字段不是直接速度指令，而是位置轨迹限速；填 0 会暂停该轴的位置轨迹。重力补偿模式仍应根据最新实测位置持续更新 `tau_ff`。

## 4. 可靠性限制

该固定帧没有 CRC。主机当前解码器检查帧头、固定长度、帧尾、ID、有限浮点数和状态，无法检测所有内容损坏。增加 CRC、序号或独立 ENABLE/DISABLE 帧需要同时修改双方协议。

3000000 baud、8N1 下：

- 72 字节指令在线传输约 0.240 ms，100 Hz 发送占 TX 方向约 2.4% 带宽
- 131 字节反馈在线传输约 0.437 ms，50 Hz 反馈占 RX 方向约 2.18% 带宽
- UART 为全双工，两个方向分别计算；桥按反馈也为 100 Hz 保守估算时仍有足够余量
- 若反馈也要达到 100 Hz，需要另外修改 STM32 的反馈周期并重新烧录；主机 `tx_hz` 不会修改固件

## 5. 代码入口

| 功能 | 文件 |
|---|---|
| 固定帧常量、编解码、分片解析 | `src/rebotarm_uart/rebotarm_uart/protocol.py` |

| 参数源 | `src/rebotarm_description/config/rebotarm_hardware.yaml` |

修改参数源后运行：

```bash
python3 scripts/sync_robot_parameters.py
```

固定七轴链路使用：

```bash
ros2 launch rebotarm_bringup grasp.launch.py \
  backend:=uart port:=/dev/serial/by-id/<STM32设备>
ros2 service call /rebotarm/enable std_srvs/srv/Trigger '{}'
ros2 service call /rebotarm/disable std_srvs/srv/Trigger '{}'
```

当前代码没有真实 STM32/CAN 实板验证；接线前必须先用逻辑分析仪或串口抓包确认帧长、字节序、绝对位置语义、反馈顺序和看门狗动作。
